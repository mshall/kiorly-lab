# Growth: provider links (GRW-P4-B1)

Status: as-built on `main`, 24 Nov 2026 (Wave W5 lane A4). Nothing is pushed or deployed. Every default marked PROPOSED_DEFAULT is a founder decision pending. Kiorex side (decision on bookings, the `acquisition` block) is P4-B2 in W7; the staff-app tab and the polished web page set are P4-B3 in W9.

## Promise
A lab can hand its own customers to its Kiorex lab page through a link or a printed QR code and see how many came and how many bookings followed. Nothing about a person, a basket or money is stored or shown here.

## What exists
- Code: `apps/api/src/modules/growth/`. Copy, never import across products: `link-code.ts`, `qr-svg.ts`, `link-tags.ts`, `link-touch.ts`, `poster-html.ts` are copies of the Clinic files (`clinics-management/apps/api/src/growth/provider-links/`); `fixtures/link-code-vectors.json` (generated by the Clinic code) and `fixtures/qr-golden.svg` (Clinic golden) prove the parity in `growth.node.test.ts`.
- Schema (migration `20261203110000_growth_provider_links`, additive): `ProviderReferralLink` (`orgId`, `branchRef`, `ownerScope` ORG|BRANCH|DESK, `channelKind`, `code` unique, `label`, `status` ACTIVE|PAUSED|REVOKED, `tags`, audit columns) and `ProviderReferralLinkDaily(linkId, date, visits, orders, completed)`. The database enforces: code is 8 Crockford characters (no I L O U), BRANCH and DESK need a `branchRef` (lab (site) id) and ORG has none, label 2 to 80 characters, `revokedAt` is set exactly when status is REVOKED, counters are not negative. There is no doctor scope. A DESK link's `label` names the reception desk.
- Link lifecycle (web `/growth/links`, app `/mobile/growth/links`): create, rename, retag, pause, resume, revoke (permanent, web only). Codes are generated with 8 random bytes masked to 5 bits (uniform), retried on collision. A plan limit caps ACTIVE plus PAUSED links (LITE 3, PRO 25, CHAIN 100; PROPOSED_DEFAULT, same as the Clinic).
- Roles (PROPOSED_DEFAULT): manage = OWNER, LAB_DIRECTOR, BRANCH_MANAGER; read (view, QR, print the reception desk card) = RECEPTION, SUPERVISOR, AUTHORIZED_SIGNATORY, FINANCE; no access = TECHNOLOGIST, PHLEBOTOMIST (403 `GROWTH_FORBIDDEN`). A lab (site)-scoped user (`StaffUser.labIds` set) sees org-wide links and links of their own lab (site) and can change only links of their own lab (site); org-wide links are head office only. Another organisation's link id is a 404 (no existence leak).
- Kiorex connection: every Growth route (web and app) answers 403 `KIOREX_NOT_CONNECTED` unless the latest `kiorex_connect.state` audit snapshot says APPROVED, or a legacy connection (no snapshot, an active KIOREX_BOOKING client, integration mode INTEGRATED). The same reading as the Connect to Kiorex front door, without the Kiorex pull.
- Registry events: creating a link queues `ReferralLinkCreated`, revoking queues `ReferralLinkRevoked` through the existing transactional outbox (validated against `@kiorex/contracts` 1.12.0 before it is stored), with `product: "LAB"`, `orgRef` = Tenant id and `clinicRef` = the lab (site) id (the contract field name is `clinicRef`). Creation is flag-gated and needs a connected organisation; **revocation is never flag-gated**. Events carry codes and ids only. Kiorex ingest of them for this product is P4-B2; until then Kiorex acknowledges unknown event shapes, so they are safe to ignore.
- Signed lookup for Kiorex: `GET /api/v1/integration/v1/referral-links/{code}` and the feed `GET /api/v1/integration/v1/referral-links?updatedSince=&limit=&cursor=` (copy of the Clinic 1.11.0 contract, `product` added), authenticated with `IntegrationAuthService` (KIOREX_BOOKING client only). The client key binds ONE organisation, so a Kiorex client can read only that organisation's links (another organisation's code is `404 REFERRAL_LINK_NOT_FOUND`). A revoke is visible immediately.
- Public resolver: `GET /api/v1/public/links/q/{code}` (no auth, no cookies). Never redirects to a caller-supplied URL: the destination is `KIOREX_PATIENT_WEB_URL` + `/lab` with `lt` (signed touch, 72 h, `{o: org, c: code, t, v:1}` HMAC with the `kx-lt1` prefix, byte-identical to the Clinic token) and the link's UTM tags, and `assertAllowedRedirect` re-checks https (http only on localhost), no userinfo and a configured host before every 302. A malformed code is 404. A paused, revoked or not-connected link still opens the plain Kiorex page (a printed QR must not break) without `lt` and without counting. `Accept: application/json` returns `{target, status}`. Rate limit 300 per minute per code (Postgres, keyed by code, never by visitor).
- Click counts: one atomic upsert per non-bot visit into the UTC-day row. No cookie, no IP, no user agent, no fingerprint is stored (the table has only counters; a test asserts the column list). Bots, link previews and prefetches are not counted (honest limit: a bot that looks like a browser is).
- QR and cards: local `qrcode`, error correction M, 4-module quiet zone (SVG and PNG). Printable A4 and A5 poster and reception desk card in Arabic (RTL) and English; PDF is the browser's Save as PDF (no server PDF engine).
- Performance (`GET /growth/performance`, counts only): visits, bookings and completed through your links versus bookings that came through the Kiorex marketplace (`LabOrder` with source KIOREX_BOOKING: RELEASED is completed, CANCELLED is lost). Until the Kiorex acquisition block arrives (P4-B2) the link `orders` and `completed` counters are 0 and every Kiorex booking is shown as marketplace (`acquisitionPending: true`). There is no money, fee or customer field in any response (tests walk the keys). Statement: "No commission is configured."
- Recommendations (`GET /growth/recommendations`, closed catalogue of five rules, ids only, wording in the web and app strings in AR and EN): `CREATE_FIRST_LINK`, `PRINT_COUNTER_CARD`, `BRANCH_NOT_LISTED`, `LINKS_UNUSED`, `HIGH_REJECTION`. A lab has no per-site listing switch, so `BRANCH_NOT_LISTED` fires (count = number of sites) while the whole Kiorex listing is paused. They use counts only and never what a person ordered or was tested for.
- Staff app API (`/mobile/growth`, `/mobile/growth/links` GET and POST, `PATCH /mobile/growth/links/:id` pause and resume only, `GET /mobile/growth/qr?linkId=`): the plan gate `mobile_staff_app` answers first (403 `FEATURE_DISABLED`), then role and connection. One call returns the whole tab (links with 30-day counts, performance, up to five recommendations, profile URL, statement placeholder, `can`, plan usage). The bootstrap module key `lab.growth` and the app tab are P4-B3 (W9); nothing in `mobile-plan` or `mobile-modules` was changed.
- Web: `/growth` ("Growth & links", Arabic default, EN, RTL, light and dark): summary tiles, links table (QR modal, copy, print AR or EN card, pause, resume, revoke with confirmation), create form, suggestions, statement placeholder, not-connected state with the Connect to Kiorex button. Strings in `apps/web/src/features/growth/growth-strings-data.ts` (merged at runtime, shared locale files only got `nav.growth`).

## Flag
`growth.provider_links` is evaluated as an entitlement key (`ENTITLEMENT_KEYS`, like `mobile_staff_app`) because a test pins `FLAG_DEFINITIONS` to the shared catalogue, which has no kiorly-lab row for it yet (TODO contracts). OFF: 403 `FEATURE_DISABLED {key, scope}` on create, QR and print; existing links keep resolving and counting, data is never hidden and a revoke still reaches Kiorex. Ships ON (ADR-023). Not a safety control.

## Configuration
`LINK_SHORT_BASE_URL` (later `https://kiorly.link`, NH-008; default `${PUBLIC_API_BASE_URL}/api/v1/public/links`), `KIOREX_PATIENT_WEB_URL` (default `http://localhost:5180`), `KIOREX_ALLOWED_REDIRECT_HOSTS`, `LINK_TOUCH_SIGNING_SECRET` (falls back to the shared webhook secret like the Clinic), `PUBLIC_LINK_RATE_PER_MINUTE`.

## Honest gaps
- Kiorex does not consume these events for pharmacy or lab yet (P4-B2): today Kiorex's link registry would register the code like a Clinic code. It decides nothing from it, because only a Clinic booking carries a clinic `lt`.
- The Kiorex brand page route (`/lab`) and its handling of `lt` are confirmed in P4-B2; the path is configuration-free for now.
- The shared flag catalogue has no kiorly-lab row for `growth.provider_links`, so ops cannot toggle it per product until contracts add one.
- No staff-app tab and no `lab.growth` bootstrap module key (W9). No server PDF. `kiorly.link` is NEEDS_HUMAN.
- Role matrix, plan limits and wording are PROPOSED_DEFAULT; Arabic wording needs native review.
