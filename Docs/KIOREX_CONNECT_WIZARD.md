# Connect to Kiorex (Kiorly Lab), ADR-040

Kiorly Lab works fully on its own. **Connect to Kiorex** (`/kiorex-connect`) guides an organisation that started standalone through joining the marketplace later.

- **Checklist.** `GET /api/v1/kiorex-connect` returns the steps computed from real state, each `done | action_needed | waiting_kiorex | blocked`, with a deep link to fix it. Lab site, test catalogue, price list completeness (every active test priced on the default list), opening hours, optional home collection, licence number per lab and an uploaded licence document, payout LABEL placeholder, terms. State is an append-only snapshot in `AuditLog` (`entityType KiorexConnect`): no schema change.
- **Request.** `POST /api/v1/kiorex-connect/request` issues a `KIOREX_BOOKING` client, switches the tenant to INTEGRATED, and sends the signed request. Kiorex runs a signed handshake against `/integration/v1/tests`.
- **Secrets.** Stored sealed in `IntegrationClient`; returned only in the rotation response; never logged or audited.
- **Enrolment code (contracts 1.9.0).** The "Request to go live" step asks for the one-time enrolment code Kiorex ops create for this organisation (Partner onboarding > Enrolment codes). The first request is signed with it; Kiorex answers with an intake key (shown once) which the product keeps sealed in its own settings column (`Tenant.kiorexIntakeKeyEnc`, migration `20261126100000_kiorex_intake_key`, backfilled from the last connect snapshot; the append-only audit snapshot no longer carries it, old snapshots keep their sealed copy) and signs every later request with (re-submit, credential rotation). Signing uses `@kiorex/contracts` 1.9.0 (`signIntakeRequest`, `deriveIntakeSigningKey`, `newIntakeNonce`), not a local copy. The code is held in the form only and is never stored. Wrong, used, expired or revoked codes all answer the same way (`ENROLMENT_CODE_REJECTED`). The old shared-webhook-secret signing is gone. Protocol: INTEGRATION.md in the workspace root and `kiorex-contracts` 1.9.0.
- **Status.** The product polls Kiorex with a status token it derives itself (HMAC of the organisation id); nothing is stored. Rejection returns the organisation to standalone.
- **After Go live.** The page offers to make Kiorex Passport the default sign-in (`defaultSignInMethod`) and to invite staff to link their phone.
- **Tests.** ``integration/kiorex-connect.node.test.ts`, `web/src/features/kiorex/kiorex-connect.node.test.ts``; end to end: `e2e/test/22-standalone-connect.e2e.ts` in the workspace repo.
- **Not done / needs a human.** Counsel-approved terms and fee wording, real notification providers, real launch-gate evidence, the production hand-over channel for enrolment codes.

## Front door: the state-aware Kiorex tab (ADR-040 amendment)

The nav item **Connect to Kiorex** (owner/director, `settings.manage`) opens a front door that picks one of five states from real state (`GET /api/v1/kiorex-connect/front-door`): NOT_CONNECTED (landing and Talk to us), IN_PROGRESS (progress and next step; the full checklist is at `/kiorex-connect/steps`), WAITING (what happens next), LIVE (dashboard) and ATTENTION (paused, changes requested, rejected: decision banner plus what is missing). Live shows Kiorex bookings this month (bookings, resulted, cancelled), recent Kiorex bookings without patient names and the lab sites. Flags are append-only audit marks (`KiorexFrontDoor`). Fees charged, rating and pause/resume are not available in the lab product, so they are not shown.
- **Wording.** All marketing text is the `kiorexMarketing` namespace (the `kiorexMarketing` block of `apps/web/src/locales/en.json` and `ar.json`). **NEEDS_HUMAN: founder and counsel approve it before launch.** It states no price and no patient number; the fee sentence is built from the published fee schedule when there is one, otherwise it says the fees are confirmed by the Kiorex team.
- **Talk to us.** Inline form (no pop-up): name, role, phone and/or e-mail, preferred time, optional note, consent to be contacted. Sent signed to Kiorex (`POST /partners/v1/leads`, secret `KIOREX_LEAD_SIGNING_SECRET`, dev default outside production only); it becomes a lead in Kiorex ops > Partner leads. Viewing the tab while standalone and pressing Start connecting send one PHI-free funnel marker each (organisation id and product only).
- **Home card.** One dismissible card on the home dashboard for standalone organisations; dismissal is stored per user in the browser and the card returns only through "Show the Kiorex card again" on the tab.
- **Tests.** Unit: `kiorex-front-door.node.test.ts` (state mapping, form validation, signing) and the locale parity tests; Playwright `e2e/kiorex-tab.spec.ts` with `playwright.kiorex-tab.config.ts` (every state, widths 360 to 2560, Arabic RTL, dark, axe, home card); real stack: `e2e/test/24-kiorex-front-door.e2e.ts` in the workspace repo.
- **Not done.** Fees charged, rating and pause/resume on the live dashboard; the home-card dismissal is per browser.
